# 和菜头文章存档、云端分析与每日调度

运行一次，只检查和菜头网站最新发布的一篇文章。发布时间换算为系统本地日期后，只有与**本次运行开始时的系统日期**相同才处理；否则正常跳过。处理流程为：保存或复用首次正文 → 调用火山方舟云端模型 → 校验七项分析 → 在正文旁保存 `分析.json`。用户与 Agent 使用同一个命令行入口。

## 环境与安装

- macOS 或 Linux，Python 3.9 及以上；需要能够通过 HTTPS 访问 `www.hecaitou.com`。
- Python 依赖包含 HTML 解析、Markdown 转换与渲染、HTML 清理和证书库；模型请求和调度服务使用标准库，正式分析需要可用的火山方舟 API Key 和对应模型的调用权限。
- 接口固定为 `https://ark.cn-beijing.volces.com/api/v3/chat/completions`，无需运行 LM Studio。Key 从工具目录 `secrets/ark_api_key.txt` 读取，文件只包含 Key 本身，可有末尾换行或 UTF-8 BOM。该 txt 已加入 Git 忽略规则，当前权限 600；克隆项目后需要单独准备密钥文件。
- 当前电脑使用系统解释器 `/usr/bin/python3`（Python 3.9.6），已满足版本要求。依赖已安装到当前用户的 Python 包目录，运行不依赖项目内的 `.venv`。
- 以下安装命令针对当前 Mac。换用其他电脑、其他登录用户或其他 Python 版本时，需要为对应解释器重新安装依赖。

在项目根目录执行安装命令：

```bash
/usr/bin/python3 -m pip install --user -r hecaitou-archiver/requirements.txt
```

## 手动运行

下列命令仍然只运行一次；每日调度及阅读页面使用独立的 `dashboard.py` 入口。

在当前项目目录中：

```bash
/usr/bin/python3 hecaitou-archiver/archive.py --output-dir './文章存档'
```

在项目根目录中，也可分行书写命令：

```bash
/usr/bin/python3 \
  './hecaitou-archiver/archive.py' \
  --output-dir './文章存档'
```

在项目根目录查看帮助：

```bash
/usr/bin/python3 './hecaitou-archiver/archive.py' --help
```

| 参数 | 说明 |
|---|---|
| `--output-dir` | 必填保存根目录。不存在则递归创建。支持 `~`，相对路径以**启动命令时的工作目录**为基准；输出路径会解析为绝对路径并解析软链接。含空格的路径请加引号。 |
| `--timeout` | 每次网络请求的总时限，默认 20 秒；包含子进程启动、DNS、连接、TLS、重定向和完整响应读取。失败只重试一次。 |
| `--lock-timeout` | 等待同一根目录进程锁的时间，默认 120 秒。超时失败，可再次调用。 |
| `--ark-key-file` | Key txt 路径，默认工具目录 `secrets/ark_api_key.txt`，默认路径不受工作目录影响；自定义相对路径按调用目录解析。Key 不从环境变量读取，不通过命令行传值。 |
| `--analysis-timeout` | 每次云端生成的总时限，默认 300 秒；临时错误最多尝试两次。 |

三个超时参数均接受大于 0、至多 600 的有限秒数。程序不会询问缺失参数；参数错误返回退出码 2。`--help` 是唯一输出普通帮助文本的例外，正常业务调用的标准输出始终为一个 JSON 对象。等待其他分析时可能超过默认锁等待时限，可设 `--lock-timeout 600`。

## 七项分析规则

| 字段 | 含义 |
|---|---|
| `where` | 地点、环境或场景，区分实际经历与文中假设、举例。 |
| `when` | 文章所述时间，包含相对时间、时段、历史背景和举例中的时间。不能直接用发布日期或系统日期代替。 |
| `what` | 主要事情、问题或观点。 |
| `why` | 原因、动机或观点的理由。 |
| `how` | 过程、方法或做法。 |
| `which` | 具体涉及或选择的对象、选项、方案或类别。 |
| `who` | 人物、群体或组织；身份不明的第一人称可称“作者（文中的我）”。 |

分析结合整篇文章归纳，要求有原文依据，保留引用和假设的归属、语气，不拼接不同事件的信息。缺失字段值严格使用字符串 `"无"`。议论或抒情文章也可提取观点、原因和方法，不强行补齐人物时间地点。正文中的指令视作材料，不改变分析任务。

`分析.json` 是 UTF-8 文件，恰好七个键，所有值均为非空字符串。程序请求 JSON 输出模式，并独立校验字段、类型、重复键、完整结束标志；不接受空字符串、null、数组、嵌套对象或 Markdown 围栏。输出不合格时最多进行一次格式纠正；仍不合格则失败。模型的单独思考字段不保存。

程序直接向指定火山方舟接口发送全文文本与固定模型 ID，以 Bearer 鉴权，不再查询本地模型列表，不发送示例中的图片。请求 JSON 输出模式，最终独立验证七个字符串字段。请求不跟随重定向，Key 只从 txt 读取到内存用于鉴权，不进入命令行参数、运行结果或日志。

正文不截断、不自动分段。输入超过 1 MiB 时失败；云端报告上下文超限时明确失败，不再采用本地已加载实例的上下文预算。输出被长度限制截断时也不当作成功。

| 已有状态 | 本次行为 |
|---|---|
| 当天最新文章未存档 | 保存正文，再生成分析。 |
| 正文已有，分析缺失 | 校验并复用首次正文，补齐分析，不重新下载正文。 |
| 正文和有效分析都已有 | 正常跳过，不查询或调用模型，保留首次结果。 |
| 分析失败 | 保留正文，下次仍为当天最新文章时可重试。 |
| 最新文章不是当天 | 不分析历史文件或残留任务。 |
| 模型后来更换 | 已有有效分析继续保留。当前版本不提供强制重新分析开关。 |
| 分析或元数据损坏 | 报错并保留文件；检查后可将分析及元数据一起移出文章目录，再按当天规则重试。 |

## 日期、最新文章和正文规则

程序请求网站公开 Blogger 订阅源 `feeds/posts/default?alt=json&max-results=1&orderby=published`，要求只返回最新一条记录。仅使用 `published` 字段，不读取 `updated` 作为发布日期，不抓取历史列表、不补抓、不回退到其他文章。

带时区的发布时间按操作系统本地时区转换；不带时区的发布时间按本地时间解释。转换考虑文章发布时间所在日期的夏令时。运行开始时固定当天日期，排队等待锁或网络请求跨午夜也不改变该次运行的日期。系统设置或进程 `TZ` 环境变量会影响本地日期；可在调用前设置 `TZ=Asia/Shanghai`。程序不提供跳过日期检查或指定历史日期的业务参数。

当天且未保存时，再访问对应文章页，以稳定文章 ID 定位 `.post-body`，验证文章标题，提取完整正文。保留段落、换行、引用、列表、文字链接和正文顺序，移除图片及其纯图片链接，不下载图片。相对文字链接转为绝对链接。HTML 表现样式不保留，网站导航、侧栏、评论和页脚不进入 Markdown。解析失败会明确报错。

## Agent 调用

Agent 直接执行同一入口，读取退出码和标准输出 JSON，无需交互或专用 SDK。以下示例以项目根目录为工作目录：

```python
import json
import subprocess

run = subprocess.run(
    ["/usr/bin/python3",
     "./hecaitou-archiver/archive.py",
     "--output-dir", "./文章存档"],
    capture_output=True, text=True, encoding="utf-8", timeout=1600,
)
result = json.loads(run.stdout)
if run.returncode != 0:
    raise RuntimeError(result["error"])
# 查看 result["archive_status"] 和 result["analysis"] 区分两个阶段。
```

外部调用总超时应覆盖锁等待、网页请求、最多两轮生成（含一次格式纠正），以及各请求的有限重试。默认配置的网络与等待上限预算约 1400 秒，示例使用 1600 秒；这是失败重试上限，正常调用通常快得多。修改内部超时后，应同步调整 Agent 的外部超时。`archive.py` 保持单次执行，每日调度由下面的本地管理服务负责。

## JSON 结果和退出码

```json
{
  "status": "saved",
  "title": "抒情的基础",
  "published_date": "2026-09-05",
  "system_date": "2026-09-05",
  "source_url": "https://www.hecaitou.com/2026/09/the-groundwork-for-romance.html",
  "output_path": "/指定目录/2026-09-05 抒情的基础/正文.md",
  "error": null,
  "archive_status": "saved",
  "analysis": {
    "status": "saved",
    "output_path": "/指定目录/2026-09-05 抒情的基础/分析.json",
    "model": "doubao-seed-2-1-turbo-260628"
  }
}
```

| 字段 | 含义 |
|---|---|
| `status` | 见下表。 |
| `title` | 文章原始标题。 |
| `published_date` | 发布时间换算到系统本地时区后的日期。 |
| `system_date` | 本次运行开始时的系统本地日期。 |
| `source_url` | 文章公开链接。 |
| `output_path` | 成功保存或已存在存档的绝对文件路径；未生成时为 `null`。 |
| `error` | 正常结果为 `null`；失败为 `{"code": "错误代码", "message": "原因"}`。 |
| `archive_status` | 存档阶段：`not_started`、`saved`、`skipped_existing`、`skipped_not_today` 或 `failed`。 |
| `analysis` | 分析阶段对象：`status`、`output_path`、`model`；尚未获取的路径和模型为 `null`。分析状态取值同上。复用分析时，`model` 为首次保存记录中的模型。 |

尚未获得的信息为 `null`。失败发生在原子提交之后时，可能已存在完整存档，下一次会校验并跳过；以实际存档完整性为准。

| status | 退出码 | 含义 |
|---|---:|---|
| `saved` | 0 | 本次成功完成新存档或补齐分析。 |
| `skipped_not_today` | 0 | 最新文章不是系统当天发布，包括未来日期。 |
| `skipped_existing` | 0 | 正文与分析均完整且已存在，无新写入。 |
| `failed` | 1 | 网络、解析、目录、文件、日志等失败。 |
| `failed` | 2 | 参数错误。 |
| `failed` | 130 | 捕获到 Ctrl+C 中断。 |

例如：正文已存在而本次补齐分析时，顶层 `status=saved`、`archive_status=skipped_existing`、`analysis.status=saved`。正文保存成功但模型失败时，顶层为 `failed`、退出码非零，`archive_status=saved`、`analysis.status=failed`，正文路径保留。运行状态与错误不会混入七字段分析文件。

进程被 SIGKILL、断电等强行终止时无法保证返回 JSON，但未完成存档不会被当成成功。

## 文件、日志和保存完整性

```text
保存根目录/
├── 2026-09-05 抒情的基础/
│   ├── 正文.md
│   ├── 分析.json
│   ├── .archive.json
│   └── .analysis.json
├── logs/
│   └── 20260905T...-随机ID.jsonl
└── .hecaitou-state/
    ├── archive.lock
    └── staging/
```

`正文.md` 为 UTF-8，第一个一级标题保持文章原题，后面只含正文。文件夹标题中的不兼容字符替换为 `_`，超长标题按 UTF-8 字节边界缩短；命名冲突增加文章 ID 的哈希后缀，仍有冲突则再加序号，已有文件不会被覆盖。

`.archive.json` 与正文同时提交，记录文章稳定 ID、首次保存时间和正文 SHA-256。去重依据文章 ID，因此标题或链接后续变化不会导致重复保存；每次跳过前验证正文哈希。不要删除或编辑这些元数据，也不要修改已保存正文；可复制一份自行编辑。检测到已有记录损坏时会报告 `archive_damaged`，不会静默覆盖。

`.analysis.json` 记录对应正文的 SHA-256、分析 JSON 的 SHA-256、模型 ID、提示词版本和时间。分析结果先写入同目录的临时文件并执行 fsync，元数据先提交，再通过原子硬链接发布 `分析.json`，目标已存在时拒绝覆盖。最终 JSON 是提交点：只存在元数据而没有 JSON 表示未完成，下次可重试；JSON 与元数据均完整则跳过。分析期间正文发生变化时拒绝提交。整个串联流程持有同一根目录的进程锁，避免并发重复生成。

同一根目录内使用操作系统 `flock` 进程锁，锁在进程退出或崩溃时自动释放。先在同一文件系统的私有临时目录完整写入正文和元数据、执行 `fsync`，再原子重命名整个目录；因此成功标记与正文同时出现。写入过程中被杀死的临时事务会在下次符合日期条件并尝试保存时清理。请保留锁文件；并发运行期间不要手工移动或修改存档根目录。支持具有正常锁及原子重命名语义的本地文件系统，不对网络盘或云同步盘的并发语义作保证。

日志每次运行单独生成 UTF-8 JSONL，记录开始时间、系统日期、时区名称与偏移、根目录、文章元数据、日期判断、请求失败与重试、成功路径、跳过原因及最终结果，也记录模型 ID、提示词版本对应的元数据、请求耗时和格式纠正。日志不保存成功回复中的模型思考内容。日志不进入标准输出；错误同时写入标准错误。根目录不可写时，仍通过 JSON 和标准错误报告问题。

## 常见错误

| error.code | 处理方式 |
|---|---|
| `argument_error` | 检查必填目录、拼写、超时范围。 |
| `dependency_error` | 为运行工具的同一个 Python 解释器按 `requirements.txt` 安装依赖；当前 Mac 使用 `/usr/bin/python3 -m pip install --user -r requirements.txt`。 |
| `network_error` | 每个请求已最多尝试两次；检查网络、代理、证书或网站状态，必要时增加 `--timeout` 后重新调用。 |
| `response_too_large` | 单响应超过 8 MiB，检查网站是否异常。 |
| `parse_error` | 元数据、标题或正文结构不符合预期，可能是网站页面变化；不会创建不完整存档或改抓其他文章。 |
| `filesystem_error` / `log_error` | 检查目标路径、权限、可用磁盘空间和日志目录。 |
| `lock_timeout` | 同目录已有运行尚未结束；稍后重试。 |
| `archive_damaged` | 检查并修复已有存档；如需重抓，可先将损坏的整篇目录移出根目录，再运行，仍只处理当天最新文章。 |
| `ark_key_error` | 检查 Key txt 是否存在、非空且可读，只能包含一个 Key。 |
| `lm_response_error` | 云端响应不是可解析的 JSON 对象。 |
| `interrupted` / `internal_error` | 查看日志与原因；中断可重新调用，内部错误需检查程序。 |
| `lm_network_error` / `lm_timeout` | 检查访问火山方舟的网络；临时错误最多尝试两次，可提高分析超时。 |
| `lm_api_error` | 云端拒绝请求，例如 Key 无效、权限不足或模型不可用；401/403/400 等明确错误不重复重试。 |
| `lm_context_exceeded` | 云端报告上下文超限，保留正文并返回错误，不截断。 |
| `analysis_input_invalid` / `analysis_input_too_large` | 检查正文编码、标题、非空内容及大小。 |
| `analysis_invalid_output` | 一次格式纠正后仍失败；检查云端响应和提示词。 |
| `analysis_damaged` / `analysis_source_changed` | 正文、分析或元数据被修改或损坏，保留现场并人工检查。 |

## 自测

自动化测试还覆盖调度时刻、重启恢复、错过不补跑、夏令时、并发、HTTP 管理接口和最新文章与分析的对应关系。

从项目根目录执行：

```bash
/usr/bin/python3 \
  './hecaitou-archiver/selftest.py'
```

自测使用合成文章和本机临时 HTTP 服务模拟相关接口，不访问外网，不调用真实模型，不修改真实文章存档。原有存档回归测试隔离模型步骤，新增串联测试走实际 HTTP 客户端。它会启动多个进程、模拟 HTTP 失败/超时/响应截断、注入磁盘写入失败，并向测试子进程发送 SIGKILL 验证正文和分析各自的中断恢复。测试夹具固定日期只存在于测试入口，业务 CLI 始终读取真实系统日期。运行环境需允许监听 `127.0.0.1` 临时端口。

结果保存在 `test-results/unit-tests.txt` 与 `test-results/summary.json`。本次串联真实运行见 `test-results/analysis-live-first.json`、`test-results/analysis-live-repeat.json` 和 [自测报告](test-results/自测报告.md)。真实文章和分析位于项目上一级的 `文章存档/`。

本次迁移只运行云端接口专项测试：`/usr/bin/python3 -m unittest discover -s tests -p test_analysis.py -v`。另可在工具目录运行 `/usr/bin/python3 live_model_selftest.py`，按存档元数据的发布时间选择最新已有 `正文.md`，直接调用云端模型，结果放在 `test-results/cloud-analysis/`；不访问网站、不改写已有正式分析。可用 `--articles-dir` 指定其他已有存档目录；缺少正文则报错。

本次使用用户指定的火山方舟 Chat Completions 接口配置，专项验证见 [云端迁移报告](test-results/cloud-analysis/验证报告.md)。

## 本地管理页面与每日调度

在项目根目录运行：

```bash
/usr/bin/python3 hecaitou-archiver/dashboard.py --output-dir './文章存档'
```

然后打开 [本地管理页面](http://127.0.0.1:8765)。页面、字体和脚本均使用本地资源，不需要前端构建，也不访问 CDN。服务仅监听 `127.0.0.1`。

| 服务参数 | 默认值与含义 |
|---|---|
| `--output-dir` | 必填，必须指向现有存档根目录；路径规则与原存档工具一致。 |
| `--port` | `8765`；端口冲突可换成其他本地端口。 |
| `--ark-key-file` | Key txt 路径，默认工具目录 `secrets/ark_api_key.txt`，默认路径不受工作目录影响；自定义相对路径按调用目录解析。Key 不从环境变量读取，不通过命令行传值。 |
| `--analysis-timeout` | 每次云端生成的总时限，默认 300 秒；临时错误最多尝试两次。 |

首次启动调度关闭，时间预设为 `14:30`，没有自动任务。修改时间后点“保存时间”，通过开关开启或关闭调度。改变开关只影响已保存时间，正在编辑但未保存的时间不会生效。“立即执行一次”与调度开关独立，不改变时间或开关，也不绕过当天最新文章规则。

| 情况 | 行为 |
|---|---|
| 正常调度 | 按系统本地时区的 HH:mm，每天最多一次自动触发。 |
| 关闭浏览器 | 调度继续，Python 服务需保持运行。 |
| 关闭调度 | 不再自动触发；当前任务继续完成。 |
| 服务重启 | 恢复时间与开关，重新计算严格晚于当前时刻的下次执行，不补跑。 |
| 更改时间 | 若新时间已过，安排明天；若今天已自动尝试过，即使改变时间也不再次自动执行。 |
| 休眠或长时间停顿 | 调度线程间隔超过一分钟或错过执行分钟时跳过，不在恢复时补跑。正常秒级轮询延迟可在当分钟触发。 |
| 电脑关机或服务退出 | 不执行；本版本不安装系统登录自启动服务。 |
| 任务仍在执行 | 手动按钮禁用，重复请求返回 409；自动调度记录为正常跳过，当天不重试。 |
| 外部 CLI 同时运行 | 通过原有存档目录锁判断忙碌，管理服务的任务正常跳过。 |
| 最新文章不是当天 | 正常跳过，不反复轮询新文章、不跨日补抓。 |
| 模型或存档失败 | 显示失败原因，调度开关不变；保留已保存正文。 |
| 系统夏令时变化 | 不存在的时间跳过当天，重复出现的时间至多自动触发一次。手动修改系统时区后请重启服务。 |

页面分别显示调度开关状态与任务运行状态，展示下次执行、最近一次运行的触发方式、时间和结果。结果分为“成功产生结果”“正常跳过”“执行失败”。后台正在运行时独立显示“执行中”。页面每 3 秒刷新状态，编辑时间不会被刷新覆盖。

阅读区域按存档元数据的**发布时间**选择本地最新文章，当天暂无新存档时保留最近文章。正文渲染为可阅读的 HTML，移除图片和可执行网页内容；七项分析显示为中文标签。正文与分析从同一文章目录读取；有效的 `分析.json` 直接展示，不受历史校验值或隐藏分析元数据影响。新文章未生成分析时不会显示旧文章分析。没有存档时显示空状态。

调度配置、最后自动执行日期及最近 100 次内部运行记录保存在 `保存根目录/.hecaitou-state/dashboard.sqlite3`，服务日志为同目录的 `dashboard.log`；原存档流程继续写入 `保存根目录/logs/`。SQLite 事务先记录自动触发日期再派发任务，服务重启不重复自动执行。同一个根目录仅允许一个管理服务实例。

停止前台服务可按 Ctrl+C；服务将停止接收新任务，并等待当前有界任务结束。配置开关原值保留，重启后恢复。如果希望关闭终端后仍运行，可在项目根目录用：

```bash
mkdir -p './文章存档/.hecaitou-state'
nohup /usr/bin/python3 hecaitou-archiver/dashboard.py --output-dir './文章存档' > './文章存档/.hecaitou-state/dashboard-console.log' 2>&1 < /dev/null &
```

已经启动的服务无需重复执行启动命令。本机页面和 API 的详细验收结果见 [调度与页面自测报告](test-results/调度与页面自测报告.md)。
